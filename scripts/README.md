# Repository control scripts

`scripts/` contains owner-side Bun + TypeScript control entrypoints and the bounded Git Town Bash harness. A script is not a public provider API unless its module/issue explicitly exposes it.

## Control-script state machine

```text
ARGS/POLICY VALIDATED → EXACT SUBJECT RESOLVED → PLAN/DRY-RUN
  → EXPLICIT APPLY/EXECUTE → OUTPUT/RECEIPT VALIDATED
  → CLEANUP/NO-DRIFT CHECK → COMPLETED
```

Blocked states include missing/mutable subject, unsafe path/remote, unadmitted mutation, secret/session exposure, stale generated bytes, provider absence, timeout, execution failure, output mismatch, or cleanup residue.

## Current entrypoints/data flow

| Entrypoint | Flow | State owner |
|---|---|---|
| `verify.ts`, `selftest.ts` | repository contracts → deterministic checks/controls | current baseline |
| `release-manifest.ts` | manifests/contracts → byte-stable portable release | convergence-owned output |
| bettor bootstrap/verify | exact bettor subject → plan/apply/lock verification | #65–#75 |
| `git-town/` | task packet → worktree/sync/eval/publish/PR receipt | merged Git governance |

Bun + TypeScript own product/control logic; Bash only owns Git/process orchestration. Dry-run is separate from apply/publish. No secret values, generic shell-over-MCP, silent provider fallback, or another subject used as PASS. New entrypoints require state machine, public/receipt contract, timeout, artifacts, cleanup, evals, controls, path owner, and rollback.
